# Add a module to a generated site

Preconditions: the working directory has `.cms-origin.json` (a generated site) — if not,
stop. Never edit `src/cms/**` (see the base's new-site skill, `references/core-sync.md`).

## Modules: commerce, booking, newsletter

The storefronts already ship in every site, gated by module flags. Enabling one is
configuration, not code:

1. **Booking only:** ask what is sold — `transport` (days: trips, tours, charters) and/or
   `stay` (nights: rooms, villas) — and `request` vs `instant`. Refuse other booking types
   (appointments, tables, events): the core does not support them. Then relabel the three
   booking term collections in `src/site.config.ts` and the `booking.filter*` messages in
   both `messages/*.json`, using the table in the base's `new-site/references/booking.md`.
2. `src/site.config.ts` → `modules.<name>: true` (the code default).
3. `src/site-seed/data.ts` → add the module's settings to `SETTINGS`
   (`module.<name>` true; commerce: `ecommerce.currency`, `ecommerce.paymentProvider`;
   booking: `booking.mode|currency|timezone|paymentProvider|depositPercent|notificationEmails`
   and `BOOKING_KINDS`) and set `SAMPLES.product` / `SAMPLES.bookingKind`.
4. `test/site/config.test.ts` → update the expected module flag.
5. `npm run db:seed-site` (writes the settings, creates the samples as drafts). The
   flag can also be flipped in Admin → Settings → Modules.
6. Nav, header cart and sitemap follow the flag automatically.
7. For ecommerce/booking also change the home page to the matching variant (the base's
   `new-site/templates/home/home.<type>.tsx.tpl`) if the site should lead with it.

## Content collections: articles, answers, scenarios

These need code, from the base's new-site templates (ask for the base checkout path):

1. Copy the collection definition from the base's `new-site/scripts/generate.mjs`
   (`ARTICLE_DEF` + `AUTHOR_DEF`, `ANSWER_DEF`, or `SCENARIO_DEF`) into
   `src/site.config.ts`, together with its category taxonomy (`categoryDef(...)` →
   `articleCategory` / `answerCategory` / `scenarioCategory`, importing
   `taxonomyCollection` from `@/cms/config`), and add both to `collections`.
2. Render `templates/content/index-page.tsx.tpl` and `detail-page.tsx.tpl` into
   `src/app/[locale]/<segment>/page.tsx` and `.../[slug]/page.tsx`, replacing
   `{{COLLECTION}}`, `{{COLLECTION_PASCAL}}`, `{{SEGMENT}}`, `{{NS}}`. Render
   `categories-index-page.tsx.tpl` and `category-page.tsx.tpl` the same way into
   `.../<segment>/categories/page.tsx` and `.../categories/[slug]/page.tsx`, with
   `{{CATEGORY_COLLECTION}}` = `<type>_category`:
   articles → `article`/`blog`/`blog`, answers → `answer`/`faq`/`faq`,
   scenarios → `scenario`/`case-studies`/`cases`.
   Articles also bring author profiles: copy `templates/content/author-page.tsx.tpl` to
   `src/app/[locale]/authors/[slug]/page.tsx` and `AuthorProfile.tsx.tpl` to
   `src/components/site/AuthorProfile.tsx` (no tokens). `src/lib/site/authors.ts` and
   the `authors` messages are already in every site.
3. Add the nav entry in `src/lib/nav.ts` `NAV_ITEMS` (before About). The messages
   namespaces already exist, but a site scaffolded before listings gained search and
   paging is missing their keys: add `search`, `searchPlaceholder`, `searchSubmit`,
   `filterByCategory`, `clear`, `results`, `noResults`, `prev`, `next`, `pageOf` to the
   collection's namespace in BOTH `messages/*.json` (and `prev`/`next`/`pageOf` to
   `authors` for a blog), copying the wording from the base's `scripts/generate.mjs`.
3b. The listings import shared files that such a site may not have yet. Copy each one
   from the base only if it is missing: `src/lib/site/content-query.ts`,
   `src/components/site/{ContentToolbar,ContentCard,Pagination}.tsx`. If you add
   `components/site/Pagination.tsx`, replace `components/shop/Pagination.tsx` with the
   base's one-line re-export so the storefront keeps one implementation.
4. `test/site/config.test.ts` → add the key and its `<type>_category` key to the
   expected collections.
5. `src/site-seed/data.ts` → `SAMPLES.<type>: true`; run `npm run db:seed-site`.

The sitemap and the home "latest" block pick the collection up automatically.

## Verify

`npm run lint && npm run type-check && npm test && npm run build`, then with the dev
server: the new index renders its empty state and its search box, `?q=nothing` says
"no results", `?page=-5` and `?category=../../etc/passwd` still answer 200, and after
publishing a sample its detail page renders.
