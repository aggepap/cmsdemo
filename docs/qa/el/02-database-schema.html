02 · Σχήμα βάσης δεδομένων & migrations

Ελέγχει τη βάση δεδομένων που δημιουργεί το ίδιο το CMS: την αλυσίδα των migrations και τον πίνακα παρακολούθησής τους, το σύνολο χαρακτήρων και τις ρυθμίσεις του διακομιστή, κάθε έναν από τους 51 πίνακες της εφαρμογής (στήλες, ευρετήρια, μοναδικά κλειδιά και ξένα κλειδιά), τους κανόνες που ισχύουν για όλο το σχήμα, τις εγγραφές που γράφουν οι εντολές seed και την ακεραιότητα των δεδομένων αφού εκτελεστούν οι υπόλοιπες λίστες ελέγχου. Χρειάζεστε πρόγραμμα-πελάτη MariaDB/MySQL συνδεδεμένο στη βάση δεδομένων δοκιμών (όλα τα ερωτήματα χρησιμοποιούν το DATABASE(), οπότε επιλέξτε την πρώτα με USE <name>;), τερματικό στον φάκελο του έργου και δικαίωμα δημιουργίας και διαγραφής μιας πρόχειρης βάσης δεδομένων. Οι αναμενόμενες τιμές προέρχονται από το src/cms/db/adapters/mysql/schema/ και το migrations/meta/0024_snapshot.json· όπου ο κώδικας και το docs/dev-guides/02-database.md διαφωνούν, υπερισχύει ο κώδικας.

Migrations

Εκτελέστε τα παρακάτω στη βάση δεδομένων δοκιμών μετά το npm run db:migrate (λίστα ελέγχου 01, περιπτώσεις SET-009/010). Τα migrations εκτελούνται από το src/cms/db/migrate.ts, που καλεί τον MySQL migrator της Drizzle μέσω της σύνδεσης της ίδιας της εφαρμογής. Η Drizzle καταγράφει κάθε εφαρμοσμένο migration στον πίνακα __drizzle_migrations (στήλες id, hash, created_at) και αποφασίζει τι θα εφαρμόσει μόνο συγκρίνοντας τη χρονοσφραγίδα when του journal με την πιο πρόσφατη created_at σε αυτόν τον πίνακα.

Πώς διαβάζονται οι πίνακες αναμενόμενων στηλών σε αυτή τη λίστα ελέγχου. Οι τύποι γράφονται όπως τους εμφανίζει η MySQL 8 στο COLUMN_TYPE. Η MariaDB διαφέρει μόνο στην εμφάνιση: το int εμφανίζεται ως int(11), το bigint ως bigint(20), το tinyint ως tinyint(4) και το json εμφανίζεται ως longtext (το JSON της MariaDB είναι ψευδώνυμο του LONGTEXT με έλεγχο json_valid). Το tinyint(1) είναι λογική (boolean) στήλη και στις δύο. Στο COLUMN_DEFAULT, η MariaDB βάζει τις προεπιλεγμένες τιμές κειμένου σε εισαγωγικά ('draft'), εμφανίζει current_timestamp() και εμφανίζει τη λέξη NULL για στήλες που επιτρέπουν NULL χωρίς προεπιλεγμένη τιμή· η MySQL 8 εμφανίζει draft, CURRENT_TIMESTAMP (με DEFAULT_GENERATED στο EXTRA) και SQL NULL. Θεωρήστε αυτές τις γραφές ισοδύναμες. «καμία» σημαίνει ότι η στήλη είναι NOT NULL χωρίς προεπιλεγμένη τιμή (MariaDB: SQL NULL στο COLUMN_DEFAULT). Για τα ξένα κλειδιά, τα NO ACTION και RESTRICT συμπεριφέρονται ίδια στην InnoDB· και τα δύο είναι αποδεκτά. Το πρωτεύον κλειδί εμφανίζεται πάντα ως PRIMARY στο ερώτημα ευρετηρίων, όποιο όνομα κι αν του έδωσε το migration. Ένα ευρετήριο με την ένδειξη «προστέθηκε από την InnoDB για το ξένο κλειδί» δεν υπάρχει στα migrations: το δημιουργεί ο διακομιστής, με το όνομα του περιορισμού, επειδή κανένα δηλωμένο ευρετήριο δεν ξεκινά με αυτή τη στήλη.

  2. Εκτελέστε το παρακάτω SQL.
SELECT o.id, o.reference, o.subtotal, o.total,
       SUM(i.line_total) AS lines_sum,
       SUM(i.line_total <> i.unit_price * i.quantity) AS bad_lines,
       GREATEST(0, o.subtotal
         - COALESCE(JSON_EXTRACT(o.metadata, '$.costs.discount'), 0)
         + COALESCE(JSON_EXTRACT(o.metadata, '$.costs.shipping'), 0)
         + COALESCE(JSON_EXTRACT(o.metadata, '$.costs.surcharge'), 0)
         + COALESCE(JSON_EXTRACT(o.metadata, '$.costs.giftWrap'), 0)) AS expected_total
FROM orders o
LEFT JOIN order_items i ON i.order_id = o.id
GROUP BY o.id, o.reference, o.subtotal, o.total, o.metadata
HAVING lines_sum IS NULL OR lines_sum <> o.subtotal
    OR bad_lines > 0 OR expected_total <> o.total;
