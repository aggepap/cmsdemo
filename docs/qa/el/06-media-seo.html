06 · Πολυμέσα, SEO & δομημένα δεδομένα

Η βιβλιοθήκη πολυμέσων (επιτρεπόμενα και απορριπτόμενα ανεβάσματα, το όριο των 10 MB, η μετατροπή σε WebP με συνοδευτικό αρχείο AVIF, ο εντοπισμός διπλοτύπων, το εναλλακτικό κείμενο (alt), η αναζήτηση, η σελιδοποίηση, η διαγραφή, ο επιλογέας στον επεξεργαστή, το δημόσιο URL του αρχείου και οι κεφαλίδες cache του), η ταυτότητα (branding) (όνομα, λογότυπο, favicon, εικόνα κοινοποίησης, χρώματα) στον ιστότοπο, στο JSON-LD και στα email, το πάνελ SEO & AEO ανά έγγραφο και οι ετικέτες που παράγει στο head της σελίδας (title, description, canonical, Open Graph, Twitter, robots, hreflang), η οθόνη SEO (ανακατευθύνσεις, παρακολούθηση 404, παρακάμψεις meta ανά διαδρομή), η διαχείριση πεδίων SEO, το sitemap.xml, οι προσθήκες του robots.txt, οι Ρυθμίσεις → Structured data και κάθε τμήμα JSON-LD που ελέγχουν, το JSON-LD προϊόντων και κρατήσεων, και η γέφυρα του Product Manager (Praion.ai) στον βαθμό που μπορεί να τη χειριστεί ένας ελεγκτής με υπογεγραμμένα αιτήματα. Οι ανακατευθύνσεις λόγω αλλαγής slug που γράφει ο επεξεργαστής, το sitemap πέραν των 200 σελίδων και το ίδιο το robots.txt βρίσκονται στις λίστες ελέγχου 01 και 03 και αναφέρονται με το ID τους. Χρειάζεστε τερματικό με curl, openssl, sha256sum, file και ImageMagick (magick ή convert)· τα jq και exiftool βοηθούν αλλά είναι προαιρετικά. Χρειάζεστε επίσης πρόσβαση στη βάση δεδομένων μέσω client και browser με εργαλεία προγραμματιστή.

Πριν ξεκινήσετε

Η λίστα ελέγχου 01 πρέπει να έχει ολοκληρωθεί (migrations, seeds, superadmin qa-admin@example.com), με τα EL και EN επιλεγμένα και στο Editing και στο Public στις Settings → Languages. Συνδεθείτε ως qa-admin@example.com, εκτός αν μια περίπτωση ελέγχου ορίζει διαφορετικά. Τα URL χρησιμοποιούν το http://localhost:3002 (npm run dev)· σε φιλοξενούμενο περιβάλλον δοκιμών χρησιμοποιήστε τη διεύθυνσή του, και διαβάστε το .data/uploads ως το CMS_UPLOAD_DIR εκείνου του περιβάλλοντος. Τα αρχεία που ανεβαίνουν αποθηκεύονται με το uuid τους χωρίς κατάληξη· το uuid είναι αυτό που αντιγράφει το κουμπί uuid σε ένα πλακίδιο του Media.

Βοηθητικές εντολές τερματικού. Στον φάκελο του έργου εκτελέστε BASE=http://localhost:3002 και έπειτα επικολλήστε αυτές τις τρεις γραμμές. Η H εμφανίζει τις ετικέτες head μιας δημόσιας σελίδας, η LD εμφανίζει κάθε μπλοκ JSON-LD και η R εμφανίζει τον κωδικό κατάστασης και τον προορισμό ανακατεύθυνσης μιας διεύθυνσης. Στέλνουν user agent ανιχνευτή (crawler), επειδή το Next.js μεταδίδει τα μεταδεδομένα μέσα στο body για τους συνηθισμένους browsers· με Googlebot οι ετικέτες βρίσκονται στο <head>. (Στην προβολή πηγαίου κώδικα ενός κανονικού browser οι ίδιες ετικέτες μπορεί να εμφανίζονται κοντά στο τέλος του εγγράφου: αυτό είναι αναμενόμενο.)

H()  { curl -s -A Googlebot "$BASE$1" | grep -oE '<title>[^<]*</title>|<meta (name|property)="[^"]*" content="[^"]*"|<link rel="(canonical|alternate|icon)"[^>]*>'; }
LD() { curl -s -A Googlebot "$BASE$1" | grep -o '<script type="application/ld+json">[^<]*</script>' | sed -e 's/<script[^>]*>//' -e 's#</script>##'; }
R()  { curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' "$BASE$1"; }

Κλήσεις API με τη συνεδρία σας. Αντιγράψτε την τιμή του cookie cms_session στο S όπως περιγράφεται στη λίστα ελέγχου 05 («Χρήση του curl με συνεδρία») και προσθέστε το -b "cms_session=$S".

Επικύρωση του JSON-LD. Το περιβάλλον δοκιμών δεν είναι προσβάσιμο από την Google, οπότε επικυρώστε τον πηγαίο κώδικα της σελίδας ως κώδικα: εκτελέστε curl -s -A Googlebot "$BASE/<path>" > page.html, ανοίξτε το https://search.google.com/test/rich-results, επιλέξτε Code, επικολλήστε ολόκληρο το αρχείο και πατήστε Test code. Για τύπους που η Google δεν εμφανίζει ως rich results (WebSite, TouristTrip, Accommodation…) χρησιμοποιήστε το https://validator.schema.org → Code snippet → επικόλληση → Run test.

  1. Σε έναν κενό φάκελο, για παράδειγμα ~/qa-media, εκτελέστε (χρησιμοποιήστε convert αντί για magick στο ImageMagick 6): 
    magick -size 4000x3000 plasma: photo-large.jpg

Ένα JPG αποθηκεύεται και σερβίρεται ως WebP

  1. Πατήστε Upload files και επιλέξτε το photo-large.jpg.
  2. Πατήστε uuid στο νέο πλακίδιο και επικολλήστε το στο τερματικό: U=<pasted uuid>.
  3. Εκτελέστε SELECT original_name, mime, size, width, height, hash, alt_text, uploaded_by FROM media_files WHERE uuid = '<uuid>';
  4. Εκτελέστε ls -l .data/uploads/$U*, file .data/uploads/$U και sha256sum .data/uploads/$U.
  • Το πλακίδιο εμφανίζεται πρώτο στο πλέγμα, με όνομα photo-large.webp, με το μέγεθός του και 1600×1200. Ο αριθμός δίπλα στο πλαίσιο αναζήτησης αυξάνεται κατά ένα. Το κουμπί uuid γράφει για λίγο copied.
  • SQL: original_name photo-large.webp, mime image/webp, πλάτος 1600, ύψος 1200, alt_text NULL, uploaded_by το id του superadmin. Το size ισούται με το μέγεθος σε bytes του .data/uploads/$U, και το hash ισούται με το sha256 του.
  • Το file αναφέρει RIFF (little-endian) data, Web/P image. Υπάρχει δεύτερο αρχείο $U.avif και είναι μικρότερο από το WebP (διατηρείται μόνο όταν είναι μικρότερο· αν λείπει, σημειώστε τα δύο μεγέθη).

Αναφ.: src/cms/core/media/service.ts (uploadMedia) · src/cms/core/media/normalize.ts (prepareUpload, webpName) · src/cms/core/media/storage.ts

Τα GIF, WebP και AVIF γίνονται δεκτά· ένα animation διατηρεί τα καρέ του

«Load more files» μετά τα 200

Προϋποθέσεις: Μόνο σε βάση δεδομένων δοκιμών. Οι παρακάτω γραμμές δεν έχουν bytes από πίσω, οπότε οι μικρογραφίες τους είναι σπασμένες· αυτό είναι αναμενόμενο.

  1. Εκτελέστε το παρακάτω SQL και έπειτα φορτώστε ξανά το /admin/media.
  2. Κάντε κύλιση μέχρι το τέλος και πατήστε Load more files.
  3. Αναζητήστε το qa-bulk-20.
INSERT INTO media_files (uuid, original_name, mime, size, width, height, hash, created_at)
SELECT UUID(), CONCAT('qa-bulk-', n.i, '.webp'), 'image/webp', 100, 10, 10,
       SHA2(CONCAT('qa-bulk-', n.i), 256), NOW() - INTERVAL 1 DAY - INTERVAL n.i MINUTE
FROM (SELECT a.d + 10 * b.d + 100 * c.d + 1 AS i
      FROM (SELECT 0 d UNION ALL SELECT 1 UNION ALL SELECT 2 UNION ALL SELECT 3 UNION ALL SELECT 4
            UNION ALL SELECT 5 UNION ALL SELECT 6 UNION ALL SELECT 7 UNION ALL SELECT 8 UNION ALL SELECT 9) a
      CROSS JOIN (SELECT 0 d UNION ALL SELECT 1 UNION ALL SELECT 2 UNION ALL SELECT 3 UNION ALL SELECT 4
            UNION ALL SELECT 5 UNION ALL SELECT 6 UNION ALL SELECT 7 UNION ALL SELECT 8 UNION ALL SELECT 9) b

    pm() { # pm METHOD PATH [BODY_FILE]

  SIG=$(printf 'PM-HMAC-SHA256\n%s\n%s\n%s\n%s\n%s\n%s' "$M" "$HOSTPORT" "$P" "$TS" "$N" "$H" \
    | openssl dgst -sha256 -hmac "$SECRET" | sed 's/^.*= //')
  curl -s -X "$M" "$BASE$P" -H 'Content-Type: application/json' -H "X-PM-Key-Id: $KEY_ID" \
    -H "X-PM-Timestamp: $TS" -H "X-PM-Nonce: $N" -H "X-PM-Signature: $SIG" ${3:+--data-binary @"$F"}; echo
}
pm GET /api/cms/pm/v1/ping | jq .capabilities

Αναμενόμενο: Το ping απαντά με ένα αντικείμενο capabilities που περιλαμβάνει "compiled_payloads": true και "alternates": false, και woocommerce ανάλογα με το αν το Commerce είναι ενεργό. Με το module ανενεργό η ίδια κλήση απαντά 404 {"ok":false,"error":"no_route"}.
