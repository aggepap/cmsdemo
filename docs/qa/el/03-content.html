03 · Περιεχόμενο: συλλογές, έγγραφα & δημοσίευση

Δημιουργία, επεξεργασία, δημοσίευση και διαγραφή περιεχομένου στο διαχειριστικό: Pages, Brands, Testimonials και Popups, κάθε τύπος πεδίου που προσφέρει ο επεξεργαστής, slugs και αυτόματες ανακατευθύνσεις, πρόχειρο / δημοσιευμένο / προγραμματισμένο / αρχειοθετημένο, μεταφράσεις, ιστορικό εκδόσεων, συγκρούσεις επεξεργασίας και κλειδώματα επεξεργασίας, προεπισκόπηση πρόχειρου, η προστασία μη αποθηκευμένων αλλαγών, η οθόνη λίστας, δικαιώματα περιεχομένου, shortcodes, εισαγωγή markdown, και πώς εμφανίζονται όλα αυτά στον δημόσιο ιστότοπο (ανανέωση cache, μπλοκ λίστας, sitemap). Τα πεδία SEO (λίστα ελέγχου 06), η συμπεριφορά των φορμών και των popups στον ιστότοπο (07), τα προϊόντα (08) και οι εμπειρίες (09) καλύπτονται αλλού. Χρειάζεστε δύο browsers (ή ένα κανονικό και ένα ιδιωτικό παράθυρο), πρόσβαση με πρόγραμμα-πελάτη βάσης δεδομένων και τερματικό στο μηχάνημα δοκιμών.

Δημιουργία πρόχειρης σελίδας

  1. Ανοίξτε το Pages και πατήστε + New.
  2. Πληκτρολογήστε QA Page One στο Title, qa-page-one στο Slug, QA required στο QA text. Αφήστε το Status — EL σε draft.
  3. Πατήστε Create Page.
  4. Εκτελέστε το παρακάτω SQL.
SELECT id, slug, locale, status, canonical_path, published_at,
       JSON_UNQUOTE(JSON_EXTRACT(data, '$.title')) AS title
FROM documents WHERE type = 'page' AND slug = 'qa-page-one';
  • Η επικεφαλίδα της οθόνης δημιουργίας γράφει New Page. Μετά το πάτημα βρίσκεστε στο /admin/page/<id> με επικεφαλίδα QA Page One και από κάτω /qa-page-one· η ένδειξη κατάστασης γράφει draft· το Version history εμφανίζει v1 (current).
  • SQL: μία γραμμή, locale el, status draft, canonical_path /qa-page-one, published_at NULL, title QA Page One.
  • Αν ανοίξετε το /qa-page-one σε παράθυρο χωρίς σύνδεση, καταλήγετε στη σελίδα «δεν βρέθηκε».

Slugs & αυτόματες ανακατευθύνσεις

Ένα νέο ή τροποποιημένο slug κανονικοποιείται κατά την αποθήκευση: πεζά, παύλες, μεταγραφή των ελληνικών, έως 96 χαρακτήρες. Χρησιμοποιήστε curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' <url> για να δείτε την κατάσταση και τον προορισμό.

Η μετονομασία δημοσιευμένης σελίδας ανακατευθύνει την παλιά διεύθυνση

  1. Ανοίξτε το QA Page One (δημοσιευμένο). Αλλάξτε το slug σε qa-page-renamed και πατήστε Save EL.
  2. Εκτελέστε την εντολή curl της εισαγωγής για τα http://localhost:3002/qa-page-one και http://localhost:3002/qa-page-renamed.
  3. Εκτελέστε το παρακάτω SQL και ανοίξτε το SEO → Redirects στο διαχειριστικό.
SELECT source, target, status_code, kind, active, reason, notes
FROM seo_redirects WHERE reason = 'slug_change' ORDER BY id;
SELECT slug, canonical_path FROM documents WHERE id = <QA Page One id>;
  • curl: το /qa-page-one απαντά 301 προς …/qa-page-renamed· το /qa-page-renamed απαντά 200.
  • SQL: μια γραμμή /qa-page-one → /qa-page-renamed, 301, literal, active 1, reason slug_change, notes Auto: the page’s address changed — old links are sent to the new one. Το canonical_path του εγγράφου είναι /qa-page-renamed.
  • Η ανακατεύθυνση εμφανίζεται στην οθόνη SEO με αυτή τη σημείωση.

Αναφ.: src/cms/core/seo/slug-change-redirect.ts · src/cms/core/documents/service.ts (nextCanonicalPath)

Ιστορικό εκδόσεων

Κάθε αποθήκευση μιας γλώσσας δημιουργεί μια έκδοση. Το πλαίσιο Version history στη δεξιά στήλη τις εμφανίζει με τη νεότερη πρώτη, με ώρες σε UTC· κάθε καρτέλα γλώσσας έχει το δικό της ιστορικό. Χρησιμοποιήστε νέα σελίδα QA History (slug qa-history, QA text x). Οι εκδόσεις διαβάζονται με:

SELECT version, JSON_UNQUOTE(JSON_EXTRACT(snapshot, '$.data.title')) AS title,
       JSON_UNQUOTE(JSON_EXTRACT(snapshot, '$.status')) AS status, created_at
FROM document_versions WHERE document_id = <id> ORDER BY version;

Κάθε αποθήκευση προσθέτει μια έκδοση

  1. Δημιουργήστε το QA History ως πρόχειρο με τίτλο History A.
  2. Αλλάξτε τον τίτλο σε History B, ορίστε published και αποθηκεύστε. Αλλάξτε τον σε History C και αποθηκεύστε.
  3. Κοιτάξτε το Version history χωρίς ανανέωση· εκτελέστε το SQL της εισαγωγής.

Αναμενόμενο: Το πλαίσιο δείχνει v3 (current), v2, v1, η καθεμία με ώρα YYYY-MM-DD HH:MM UTC· μόνο οι v2 και v1 έχουν κουμπί Restore. Η λίστα ενημερώνεται μετά από κάθε αποθήκευση χωρίς ανανέωση. SQL: A/draft, B/published, C/published.

Συγκρούσεις επεξεργασίας & κλειδώματα επεξεργασίας

Ο browser A είναι ο qa-admin@example.com (όνομα QA Admin)· ο browser B είναι ο qa2@example.com (όνομα QA Second). Χρησιμοποιήστε το QA Translate (υπάρχουν EL και EN).

  3. Στην καρτέλα 2 (χωρίς ανανέωση) αλλάξτε τον τίτλο EL σε Tab two και πατήστε Save EL.
  • Οι καρτέλες δείχνουν τη διακριτική πορτοκαλί σημείωση You have this open in another tab. Whichever tab you save last wins.
  • Η αποθήκευση της καρτέλας 2 απορρίπτεται με το κόκκινο πλαίσιο This document changed in another tab or by another editor while you were working. Reload to see the current version — saving now would overwrite their changes. Ο αποθηκευμένος τίτλος παραμένει Tab one.

Οθόνη λίστας: αναζήτηση, φίλτρο, σελιδοποίηση

Η λίστα δείχνει μία γραμμή ανά έγγραφο με μία ετικέτα ανά γλώσσα, 25 γραμμές ανά σελίδα. Η αναζήτηση, η κατάσταση και η σελίδα διατηρούνται στη γραμμή διευθύνσεων ως ?q=, &status=, &page=.

Δημιουργία 210 δημοσιευμένων σελίδων για τις περιπτώσεις λίστας και sitemap

Προϋποθέσεις: Μόνο σε βάση δεδομένων δοκιμών. Αφαιρέστε τες με την περίπτωση καθαρισμού στο τέλος.

  1. Εκτελέστε το παρακάτω SQL.
  2. Στο διαχειριστικό ανοίξτε οποιαδήποτε σελίδα και πατήστε μία φορά Save EL (οι λίστες σελίδων στην cache ανανεώνονται μόνο με εγγραφή μέσω του CMS).
  3. Ανοίξτε τη λίστα Pages.
INSERT INTO documents (type, slug, locale, status, published_at, translation_group_id, canonical_path, data)
SELECT 'page', CONCAT('qa-bulk-', n.i), 'el', 'published', NOW() - INTERVAL n.i MINUTE,
       UUID(), CONCAT('/qa-bulk-', n.i), JSON_OBJECT('title', CONCAT('QA bulk ', n.i))
FROM (SELECT a.d + 10 * b.d + 100 * c.d + 1 AS i
      FROM (SELECT 0 d UNION ALL SELECT 1 UNION ALL SELECT 2 UNION ALL SELECT 3 UNION ALL SELECT 4
            UNION ALL SELECT 5 UNION ALL SELECT 6 UNION ALL SELECT 7 UNION ALL SELECT 8 UNION ALL SELECT 9) a
      CROSS JOIN (SELECT 0 d UNION ALL SELECT 1 UNION ALL SELECT 2 UNION ALL SELECT 3 UNION ALL SELECT 4
            UNION ALL SELECT 5 UNION ALL SELECT 6 UNION ALL SELECT 7 UNION ALL SELECT 8 UNION ALL SELECT 9) b
      CROSS JOIN (SELECT 0 d UNION ALL SELECT 1 UNION ALL SELECT 2) c) n
WHERE n.i <= 210;

Αναμενόμενο: Εισάγονται 210 γραμμές. Το σύνολο της λίστας κάτω από τον πίνακα αυξάνεται κατά 210 και δείχνει Page 1 of N με N ≥ 9. Το /qa-bulk-7 εμφανίζει QA bulk 7.
