Πριν ξεκινήσετε

Η λίστα ελέγχου 01 πρέπει να έχει ολοκληρωθεί (migrations, seeds, superadmin qa-admin@example.com). Συνδεθείτε ως qa-admin@example.com, εκτός αν μια περίπτωση ελέγχου ορίζει διαφορετικά. Τα URL χρησιμοποιούν το http://localhost:3002 (npm run dev)· ένα build παραγωγής (npm run build και έπειτα npm run start, βλ. SET-030) απαντά στο http://localhost:3000· σε φιλοξενούμενο περιβάλλον χρησιμοποιήστε τη διεύθυνσή του. Οι διαδρομές του διαχειριστικού προϋποθέτουν ADMIN_PATH=admin.

Τερματικό. Στον φάκελο του έργου εκτελέστε BASE=http://localhost:3002 και αντιγράψτε το cookie cms_session του διαχειριστικού στο S, όπως περιγράφεται στη λίστα ελέγχου 05 («Χρήση του curl με συνεδρία»). Μόλις οριστεί το CMS_CRON_SECRET (OPS-025), εκτελέστε επίσης CRON='<value of CMS_CRON_SECRET>'. Δώστε σε κάθε curl που υπόκειται σε όριο αιτημάτων το δικό του -H 'X-Real-IP: 10.10.0.N' (νέο N ανά περίπτωση), ώστε οι περιπτώσεις να μην εξαντλούν η μία το όριο της άλλης· η επανεκκίνηση της εφαρμογής μηδενίζει όλους τους μετρητές ορίων.

Ρυθμίσεις από το τερματικό. Μια αλλαγή ρύθμισης μέσω API είναι:

curl -s -X PATCH "$BASE/api/cms/settings" -b "cms_session=$S" \
  -H 'Content-Type: application/json' -H 'X-Real-IP: 10.10.0.1' \
  -d '{"seo.sitemapExtraUrls":"https://example.com/qa-ops"}' -w '\n%{http_code}\n'

Ρυθμίσεις στη βάση δεδομένων. Οι τιμές είναι JSON (οι συμβολοσειρές διατηρούν τα εισαγωγικά τους). Η στήλη του κλειδιού ονομάζεται key και πρέπει να μπαίνει σε backquotes:

SELECT `key`, value, updated_by, updated_at FROM site_settings ORDER BY `key`;

Caches. Οι αναγνώσεις ρυθμίσεων παραμένουν στην cache μέχρι να τις καθαρίσει μια αποθήκευση· δεν λήγουν ποτέ με χρονόμετρο. Αφού αλλάξετε το site_settings απευθείας με SQL, κάντε επανεκκίνηση της εφαρμογής πριν δείτε το αποτέλεσμα (η OPS-005 δείχνει γιατί).

Καταγράψτε την έξοδο του παραπάνω ερωτήματος site_settings πριν ξεκινήσετε. Η OPS-066 επαναφέρει το site με βάση αυτήν.

Μια απευθείας αλλαγή στη βάση δεδομένων δεν φαίνεται μέχρι μια αποθήκευση να καθαρίσει την cache

Προϋποθέσεις: Ένα build παραγωγής ή το φιλοξενούμενο περιβάλλον δοκιμών (ο dev server μπορεί να ξαναδιαβάσει την τιμή).

  1. Εκτελέστε curl -s "$BASE/sitemap.xml" | grep -c 'qa-ops-direct' (αυτό φορτώνει επίσης τη ρύθμιση στην cache).
  2. Εκτελέστε INSERT INTO site_settings (`key`, value) VALUES ('seo.sitemapExtraUrls', JSON_QUOTE('https://example.com/qa-ops-direct')) ON DUPLICATE KEY UPDATE value = VALUES(value);
  3. Επαναλάβετε το curl.
  4. Στο διαχειριστικό αλλάξτε οποιαδήποτε άλλη ρύθμιση (για παράδειγμα το Support email) και πατήστε Save settings. Επαναλάβετε το curl.
  5. Αδειάστε το Sitemap — extra URLs και αποθηκεύστε.

Αναμενόμενο: Τα βήματα 1 και 3 τυπώνουν 0: μια τιμή που γράφεται απευθείας στον πίνακα δεν είναι ορατή, επειδή οι ρυθμίσεις μένουν στην cache χωρίς λήξη. Το βήμα 4 τυπώνει 1: οποιαδήποτε αποθήκευση στο διαχειριστικό καθαρίζει όλες τις αναγνώσεις ρυθμίσεων. (Και μια επανεκκίνηση θα την έδειχνε.) Πρόκειται για τεκμηριωμένη συμπεριφορά, όχι για σφάλμα· το προσωπικό λειτουργίας δεν πρέπει να επεξεργάζεται χειροκίνητα το site_settings σε ζωντανό site.
