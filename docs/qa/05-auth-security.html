05 · Authentication, users, roles & security

Admin sign-in and its throttles, the session cookie and its expiry, two-factor authentication (authenticator app, recovery codes, the “Require two-factor authentication” setting and the recovery PIN), the Users and Roles screens with the rule that nobody can grant or change more than they hold, the Access permission on screens and API, Product Manager API keys and signed requests, the audit log, the cross-origin check, public rate limits, encryption of stored secrets, the role seeds and known gaps. The sign-in page layout, the next redirect, idle sign-out, the 403 page and the sidebar per role are in checklists 01 and 04 and are referenced by ID. Shop customer accounts are in checklist 08. You need two browsers (or one normal and one private window), a phone with an authenticator app (Google Authenticator, Microsoft Authenticator, 1Password or similar), a terminal with curl, openssl and sha256sum, database client access, and permission to edit .env.local and restart the server.

Before you start

Checklist 01 must be done (migrations, seeds, superadmin qa-admin@example.com) and ADM-001 in checklist 04 (roles QA limited and QA no access; users qa-editor@example.com, qa-limited@example.com, qa-noaccess@example.com, qa-en@example.com). URLs use http://localhost:3002 (npm run dev); on a hosted test environment use its address. “Signed in as X” means sign in at /admin/login with that account. The API does not use an Authorization header: browser calls carry the cms_session cookie, and Product Manager keys sign each request with X-PM-* headers.

Using curl with a session. Sign in, open developer tools → Application (Chrome) or Storage (Firefox) → Cookies → the site, and copy the value of cms_session. In the terminal run BASE=http://localhost:3002 and S='<pasted value>', then add -b "cms_session=$S" to a curl command. curl sends no Origin header, so the cross-origin check lets it through; that is by design (see AUTH-078).

Sign-in with curl. The login API needs a reCAPTCHA token when both RECAPTCHA_* keys are set. For the curl sign-in cases, blank RECAPTCHA_SITE_KEY= and RECAPTCHA_SECRET_KEY= in .env.local and restart; the login page then shows no captcha box. Restore the keys at the end. Rate limits are kept in server memory per X-Real-IP header value; restarting npm run dev empties them. In development curl may set X-Real-IP itself; behind nginx the proxy overwrites it.

Sessions

The session is a signed token in the cms_session cookie. It has an idle deadline (ADMIN_SESSION_IDLE_MINUTES, default 60) that moves forward while you work, and an absolute deadline (ADMIN_SESSION_TTL_HOURS, default 8) that never moves. The on-screen idle warning and sign-out are SET-054, SET-055 and ADM-039 to ADM-041; the Sign out button is ADM-020.

Session cookie flags

  1. Sign in and open developer tools → Application → Cookies → the site.
  2. Select cms_session and read the flag columns.
  3. In the Console tab run document.cookie.
  4. Repeat steps 1–2 on the HTTPS test environment.
  • HttpOnly ticked, SameSite Lax, Path /, an expiry about 60 minutes ahead (not “Session”).
  • document.cookie does not contain cms_session.
  • On localhost over HTTP Secure is not ticked; on the HTTPS test environment (a production build) Secure is ticked.

The session slides forward while you work

  1. Signed in, run curl -s -b "cms_session=$S" "$BASE/api/cms/auth/me" and note sessionExpiresAt.
  2. Note the cms_session expiry in developer tools.
  3. Wait at least 70 seconds, then click any admin link (the page sends a keepalive to /api/cms/auth/me; watch it in the Network tab).
  4. Look at the response headers of that request and at the cookie expiry again.
  • Step 1 answers 200 with {"ok":true,"data":{"userId":…,"email":"…","sessionExpiresAt":…}}, an epoch-seconds value about 3600 seconds after sign-in.
  • The keepalive response carries a Set-Cookie: cms_session=… header, and the cookie expiry moved forward by about the time you waited. It never moves past 8 hours after sign-in.

  1. In a terminal make a key and keep the terminal open: 
    KEY_ID=$(openssl rand -hex 6)
