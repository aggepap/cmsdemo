The shop end to end: categories (nested), tags, size charts and products (simple, with variations, external, digital and gift card) in the admin; the shop, category, tag and product pages in both languages, filters and search; the browser cart; checkout with addresses, both shipping engines, cash on delivery, coupons, gift wrap and gift cards; Stripe, PayPal and Viva in sandbox (success, decline, cancel, webhooks, replays); the checkout's refusals; the confirmation screen and the order emails; the Orders screen (list, detail, status lifecycle, conflicts, refunds, the refund-required notice, stock); shipments, courier credentials and BoxNow vouchers against the BoxNow stage API; the stale-order, gift card and abandoned-cart jobs; customer accounts, the Customers screen, reviews, the wishlist and the marketplace feeds. Covered elsewhere and referenced by ID: the Commerce and Customer accounts switches and their 404s (SET-034 to SET-037, SET-040, SET-042), the admin bar on shop pages and a signed-in customer (ADM-024, ADM-026, ADM-060), Customer accounts on while Commerce is off (ADM-012), the Gift cards entry (ADM-037), the commerce tables and money invariants (DB-037 to DB-050, DB-090, DB-094, DB-095), the customer cookie refused by the admin API (AUTH-015), the permission matrix (AUTH-055), shop addresses in the sitemap (MED-079), product JSON-LD (MED-093), Product Manager slug redirects (MED-102) and the unsubscribe page itself (MKT-048). You need: a test environment reachable from the internet (for PayPal and Viva webhooks), sandbox accounts at Stripe, PayPal and Viva, BoxNow stage credentials, a mailbox you can read as the customer and one as the shop, database client access, a terminal with curl, and two browsers (or a normal and a private window).

Before you start

Checklists 01 (migrations, seeds, superadmin qa-admin@example.com) and 07 (MKT-001: outgoing mail configured) must be done. Sign in as qa-admin@example.com unless a case says otherwise. URLs use http://localhost:3002; on the hosted test environment use its address. Greek is the default language and has no prefix: /shop is Greek, /en/shop English. Most steps use the English pages so the quoted text can be compared directly; Greek wording is given where a case is about language.

Never use live keys. Every payment and courier variable below must hold a sandbox or test value: Stripe keys starting sk_test_ / pk_test_, PAYPAL_ENV=sandbox, VIVA_ENV=demo, and BOXNOW_API_URL empty or pointing at https://api-stage.boxnow.gr/api/v1. Use each provider's documented sandbox test cards and accounts; this page names them generically (“the provider's successful test card”).

Terminal. In the project folder run BASE=http://localhost:3002, CRON='<value of CMS_CRON_SECRET>', and copy the admin cms_session cookie into S as in checklist 05 (“Using curl with a session”); add -b "cms_session=$S" to admin calls. Public endpoints are rate limited per address: give each curl its own -H 'X-Real-IP: 10.80.0.N' (a new N per case).

Order at a glance. Many cases end with this query; replace the reference:

SELECT o.id, o.reference, o.status, o.subtotal, o.total,
       JSON_EXTRACT(o.metadata,'$.costs') AS costs, JSON_EXTRACT(o.metadata,'$.coupon') AS coupon,
       JSON_EXTRACT(o.metadata,'$.codAmount') AS cod, JSON_EXTRACT(o.metadata,'$.stockTaken') AS stock_taken,
       p.id AS pay_id, p.provider, p.status AS pay_status, p.amount, p.provider_ref
FROM orders o LEFT JOIN payments p ON p.order_id = o.id
WHERE o.reference = 'ORD-2026-XXXXXXXXXX';

Stock at a glance. SELECT locale, JSON_EXTRACT(data,'$.stock') AS stock, JSON_EXTRACT(data,'$.variations[*].stock') AS var_stock FROM documents WHERE type = 'product' AND slug = '<slug>'; Stock is shared: every language row must show the same numbers.
