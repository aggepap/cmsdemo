Before you start

Checklist 01 must be done (migrations, seeds, superadmin qa-admin@example.com), with EL and EN both ticked for Editing and Public in Settings → Languages. Sign in as qa-admin@example.com unless a case says otherwise. URLs use http://localhost:3002 (npm run dev); on a hosted test environment use its address, and read .data/uploads as the CMS_UPLOAD_DIR of that environment. Uploaded files are stored under their uuid with no extension; the uuid is what the uuid button on a Media tile copies.

Terminal helpers. In the project folder run BASE=http://localhost:3002, then paste these three lines. H prints the head tags of a public page, LD prints each JSON-LD block, R prints the status code and redirect target of an address. They send a crawler user agent, because Next.js streams metadata into the body for ordinary browsers; with Googlebot the tags are in <head>. (In view-source in a normal browser the same tags can appear near the end of the document: that is expected.)

H()  { curl -s -A Googlebot "$BASE$1" | grep -oE '<title>[^<]*</title>|<meta (name|property)="[^"]*" content="[^"]*"|<link rel="(canonical|alternate|icon)"[^>]*>'; }
LD() { curl -s -A Googlebot "$BASE$1" | grep -o '<script type="application/ld+json">[^<]*</script>' | sed -e 's/<script[^>]*>//' -e 's#</script>##'; }
R()  { curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' "$BASE$1"; }

API calls with your session. Copy the cms_session cookie value into S as described in checklist 05 (“Using curl with a session”) and add -b "cms_session=$S".

Validating JSON-LD. The test environment is not reachable from Google, so validate the page source as code: run curl -s -A Googlebot "$BASE/<path>" > page.html, open https://search.google.com/test/rich-results, choose Code, paste the whole file and click Test code. For types Google does not show as rich results (WebSite, TouristTrip, Accommodation…) use https://validator.schema.org → Code snippet → paste → Run test.
