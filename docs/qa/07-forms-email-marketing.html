You need a mailbox you can read for CONTACT_RECIPIENT_EMAIL, a second address to act as a visitor, a terminal with curl and openssl, database client access, and a browser with developer tools plus a private window.

Before you start

Checklist 01 must be done (migrations, seeds including npm run db:seed-cookies from SET-018, superadmin qa-admin@example.com). Sign in as qa-admin@example.com unless a case says otherwise. URLs use http://localhost:3002; on a hosted test environment use its address. Greek is the default language and has no prefix: /contact is Greek, /en/contact English.

Terminal. In the project folder run BASE=http://localhost:3002. For admin API calls copy the cms_session cookie into S as in checklist 05 (“Using curl with a session”) and add -b "cms_session=$S". Public endpoints are rate limited per address; give each curl its own -H 'X-Real-IP: 10.70.0.N' (a new N per case) so one case does not use up another's budget.

Visitor browser. “Fresh private window” means: close every private window, open a new one. Its Local Storage (developer tools → Application → Local Storage in Chrome, Storage in Firefox) then holds none of the site-… keys. The keys used here are site-cookie-consent, site-cookie-categories, site-visitor-ref and site-popup-seen.

Forget a cookie decision. The banner cannot be reopened from the site (see MKT-054). To be asked again in the same window, run this in the console and reload:

localStorage.removeItem('site-cookie-consent'); localStorage.removeItem('site-cookie-categories');
