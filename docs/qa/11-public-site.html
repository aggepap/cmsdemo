11 · Public site, languages, accessibility & performance

The cross-cutting pass over the public site as a visitor sees it. Covered here: every public route loading in Greek and English, the address rules of the proxy (unprefixed Greek, /en, /el and /home redirects, no browser-language detection), header, footer and mobile menu links, the language switcher, translated interface text and messages/*.json parity, price, date and number formats per language, the home page sections and their empty states, images, the shared behaviour of public forms, an accessibility pass against WCAG 2.2 AA (keyboard, focus, skip link, landmarks, headings, contrast, zoom and reflow, reduced motion, screen readers), layout at five widths, browser coverage, Lighthouse and Core Web Vitals, caching headers, console and network errors, favicon and theme colour, print, and what happens with the database down or on a slow network. Covered elsewhere and referenced by ID: language switches in Settings (SET-044 to SET-049), module switches (SET-033 to SET-043), security headers and robots.txt (SET-073 to SET-078), CMS page rendering, publishing and preview (CON-004, CON-065, CON-094, CON-099), the admin bar (ADM-022 to ADM-034, ADM-060), head tags, hreflang, sitemap, structured data and 404 logging (MED-035 to MED-039, MED-060 to MED-062, MED-078 to MED-096), media file headers (MED-026 to MED-029), branding and colours (MED-030 to MED-034), the contact form (MKT-003 to MKT-015), newsletter signup (MKT-030 to MKT-036), the cookie banner (MKT-049 to MKT-058), popups (MKT-080 to MKT-094), shop, cart, checkout and accounts (COM-015 to COM-032, COM-095 to COM-103), booking pages and forms (BKG-011 to BKG-016, BKG-042 to BKG-046, BKG-091). You need: a production build of the site with commerce, booking, customer accounts, wishlist and newsletter on and the QA data of checklists 08 and 09; Chrome (with Lighthouse in developer tools), Firefox, Safari on a Mac or an iPhone, and Samsung Internet on an Android phone if available; NVDA on Windows and/or VoiceOver on macOS or iOS; a terminal with curl and node; and shell access to stop the database for one case.

Before you start

Checklist 01 must be done. Performance, caching and header cases need a production build (npm run build then npm run start, see SET-030), which answers on http://localhost:3000; the dev server (npm run dev, port 3002) is slower, sends no CSP and must not be used for Lighthouse. On a hosted environment use its address. Greek is the main language and has no prefix; English lives under /en (SET-044).

Terminal. In the project folder run BASE=http://localhost:3000. A quick status check of one address is curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' "$BASE/about".

Windows. Unless a case says otherwise, run public cases in a private window where you are not signed in to the admin, so the admin bar does not appear. Where a case says “signed in as customer”, use the customer account from COM-095.

Widths. Use the browser's responsive / device mode and type the width in. 320 px is the WCAG reflow width; 375 px is a small phone; 768 px is where the desktop header appears (Tailwind md); 1024 px and 1440 px are laptop and desktop.

Prepare the site for this checklist

  1. In Settings → Modules tick Commerce, Booking, Customer accounts and Newsletter and click Save settings. In Settings → Ecommerce → Wishlist switch the wishlist on.
  2. In Settings → Languages check that EL and EN are both Public.
  3. Make sure the pages home, about, contact, privacy and terms are published in both languages (run npm run db:seed-site -- --force --publish-samples as in SET-021 if they are still drafts).
  4. Make sure at least one published product with an image, a category, a tag and one published booking experience exist in both languages (from checklists 08 and 09), and one customer account with a placed order (COM-101). Write down: product slug <p>, category slug <c>, tag slug <t>, experience slug <x>, order reference <ref>.
  5. Create one page QA EL Only (slug qa-el-only), published in Greek only; leave its English version empty.

Expected: Every item above exists. The header of / shows Αρχική, Κρατήσεις, Κατάστημα, Σχετικά, Επικοινωνία, a heart (wishlist), an account icon and a cart icon.

Address rules: /, /el, /home, trailing slash, browser language and cookie

  1. Run each command and write down the status and redirect target: 
    for p in / /en /el /el/about /home /en/home /en/ /about/; do
  printf '%-12s ' "$p"; curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' "$BASE$p"; done
curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' -H 'Accept-Language: en-US,en;q=0.9' "$BASE/"
curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' -b 'NEXT_LOCALE=en' "$BASE/about"
  2. In a browser whose preferred language is English, open /.
  • / and /en: 200, no redirect. There is no redirect from / to a language prefix; Greek is served at the root.
  • /el → / and /el/about → /about (307 or 308). /home → / and /en/home → /en with 308. /en/ and /about/ redirect once to the address without the slash.
  • Accept-Language English and the NEXT_LOCALE=en cookie both still give 200 with no redirect, and the browser in step 2 shows the Greek home (no language detection, as SET-045).
