CMS manual QA

04 · Admin UI & navigation

The admin shell and everything around the content: the sign-in page, the dashboard, the sidebar per module and per role, the top bar and sign out, “Back to site”, the admin bar on the public site, the 403 page, idle sign-out, the shared controls (tabs, dialogs, messages, tables, the unsaved-changes guard), every admin screen loading with its empty state, the admin under a moved path, phone-width layout, keyboard and screen-reader use, and the colour scheme. Editing documents, fields, publishing, versions, locks, list search and delete rights are in checklist 03; sign-in security, two-factor and role editing in 05. You need two browsers (or one normal and one private window), a terminal on the test machine to edit .env.local, and for the accessibility cases a screen reader (NVDA, VoiceOver or Narrator) or the browser's accessibility tree.

Before you start

Checklist 01 must be done: migrations applied, the superadmin qa-admin@example.com exists and the seeded pages were published with npm run db:seed-site -- --force --publish-samples. The URLs below use http://localhost:3002; on a hosted test environment use its address instead. The admin is at /admin unless a case says otherwise. “Signed in as X” means sign in at /admin/login with that account (tick the reCAPTCHA box; complete two-factor setup if asked, see checklist 05). Cases that need the shop or bookings expect the content from checklists 08 and 09 (at least one published product in a published category and tag, and one published experience); if those modules are off on the site under test, mark those cases N/A.

Create the accounts used by the role cases

  1. Signed in as qa-admin@example.com, open Roles. Under Add a role enter Role name QA limited, leave Access ticked, tick View media and View audit log only, click Add role.
  2. Add a second role QA no access: untick Access, tick View content, click Add role.
  3. Open Users. Under Add a user create, clicking Add user each time: qa-editor@example.com (name QA Editor, role editor), qa-limited@example.com (name QA Limited, role QA limited) and qa-noaccess@example.com (name QA No Access, role QA no access), each with a strong password such as Qa-Admin-Ui-Pass-2026!.
  4. In a terminal run npm run db:seed-admin -- qa-en@example.com 'Qa-English-Pass-2026!' 'QA English' --locale en.
  • While Access is unticked in step 2 an amber note reads Without Access this role cannot open the admin at all — every screen will refuse it. The role is still saved.
  • All four users are created without error. qa-en@example.com is a superadmin whose account language is English.
